> **读者**：一个刚入行的后端同事。他懂数据库、懂接口、懂缓存，**但没碰过 AI**。

## 一、RAG 是什么

把电脑里的资料**切成小块**，每次你提问时，**先挑出最相关的几块**，连同问题一起交给模型，并要求它**只依据这几块**回答。

**它治的是「模型根本不知道这件事」。**

不是让模型变聪明——**模型的能力一点没变，变的是它手里有没有这份资料。**

> 一句话对比：
> **不用 RAG** = 闭卷考试，靠它自己背过的东西答。
> **用 RAG** = 开卷考试，但它只准翻你递过去的那几页。

`✏️` 补：**"在可控范围内提高正确率"**这个说法也成立，但它是**果**不是**因**——因为能补上模型不知道的，所以才在资料界定的范围内答得准。写定义时两半都要有。

## 二、一条流水线，5 环

从「一个 `.md` 文件」到「屏幕上出现答案」，数据流过这 5 步（就是我自己写的那些函数）：

```
1 切分          2 向量化          3 检索            4 拼提示        5 生成
split_chunks →  embed → res   →  retrieve      →  build_prompt →  ask
（切成小段）    （算成向量存起来）  （算分+排序+取3个）  （把段落和问题拼）  （发给模型）
```

**关键：1、2 两步只在程序启动时做一次（文档没变就不用重做）；3、4、5 每问一次做一遍。**

`✏️` 补：文档向量**只算一次**，是因为**每次提问都重算一遍会特别慢，而文档内容没变**——所以要把结果存下来（存在 `res` 这个变量里）。这个"存"的动作，工业上换成了**向量数据库**：它干的是同一件事，只是能装下千万级、还能持久化。**我没用数据库，因为我的语料只有 23 段。**

## 三、为什么每一环都要有

把某一环拿掉，或者**换成一个"更笨的版本"**，系统会怎样坏？（**换笨版本比直接拿掉更可怕——因为它照样跑通，坏得静悄悄。**）

| 环 | 换成的笨版本 | 坏在哪 | 我的证据 |
|---|---|---|---|
| **1 切分** | 不切，整篇当 1 段 | 关键信息被稀释掉、答不到点上 | Day 3：只有 10 段时**找不到答案**，切成 23 段后找到了 |
| | `✏️` 切太细 | **两头的坏**：太粗→长段稀释；太细→空壳段抢分 | Day 6：`## 三、B 线` 被切剩 **28 字**，反而**霸占第 1 名** |
| **2 向量化** | 关键词匹配（不算向量） | **换个说法就失效**；不能靠语义靠近 | Day 6：问「**B 线**有哪几个项目」，B1-B5 五段正文里**一个字都没有"B 线"**→ 关键词判它们完全无关 → 答案段全灭。而向量能靠语义靠近（Day 4：同一段问 KV Cache 得 **0.4915**、问红烧肉得 **0.1401**，差 3.5 倍） |
| **3 检索** | `k=1`（只要最像的那一段） | **多跳问题永远答不出**——答案要好几段并起来才完整 | Day 6：问「B 线有哪几个项目」，top-1 给了**空壳段/元信息段**，真正装答案的五段全落榜 |
| | `k=全部`（23 段全塞） | 噪声灌进来，成本涨 | 真命中 **0.4424** ≈ 高相关无答案 **0.4015**——**分数分不开"像"和"有答案"**，塞满了模型更容易被"最像的错段"带跑 |
| **4 拼提示** | 删掉那句约束（"只依据资料，没有就说没有"） | `✏️` **原以为**会改用自己的知识回答 → 脱离资料、开始编。**实测：不会。** | Day 5：段落"高相关但没答案"（0.4015），模型顶住没编。我当时判"功劳全在那句约束"——**Day 7 实测把这条推翻了** |
| | `✏️` 实测①：把**两处**约束全清掉 | **行为几乎没变**——照样不编、照样只用资料 | 问「推荐三本 RAG 的书」仍答"资料中并未推荐"；问「KV Cache 是什么」**仍只复述资料里那张表格**（空间换时间/命中率/失效策略） |
| | `✏️` 实测②：**同一问题走 `day1.py`（完全不发资料）** | **它给出了一整篇真正的技术解释**——足以证明**它知道**，只是在资料结构下**选择不说** | `day1.py` 只有 `{"role":"user","content":"KV Cache 是什么"}`，无资料、无 persona → 答案覆盖：自注意力的 K/V、`O(N²)→O(N)`、**PagedAttention / vLLM**、**MQA/GQA**、滑动窗口、KV 量化 |
| | `✏️` **结论：那句约束管什么？** | **"把资料塞进 prompt"这个结构本身就是约束**，提示词那句只是**冗余的第二道安全带**——**边际价值接近零** | 三次实验：约束在 → 不编；约束清空 → 不编；**资料整个不发 → 长篇解释**。变量只有一个：**有没有资料块** |
| | `✏️` **"拦路虎"到底是什么？** | **不是那句提示词，是结构。** 删掉提示词 ≠ 打开模型的知识 | 所以"删掉约束就能答得更好"**不成立**。真正的病是：**该用模型自己的知识时，结构不让它用** |
| **5 生成** | 不控制随机性（`temperature`） | 同一问题、同一资料，**答案会抖** | 实测：正文没变，**引用编号 `[1][2][3]` ↔ `[1][2]` 在抖** |
| | 不设超时（`timeout`） | **无限等**——不是 30 秒，是一直等下去 | 实测：**卡了十分钟**，没有报错、没有输出 |

### 一句话总结这 5 环

> **前四环我都能算、能控、能复现；只有第 5 环，我发出去之后只能等。**
> 所以所有防线（超时、温度、兜底指令）本质上都是——**在给一个我控制不了的东西装护栏。**

## 四、最反直觉的两件事

**1. RAG 不是"一定更准"，有时反而更差。**

资料跟问题无关时，模型本来还能靠自己的知识答；带上资料 + 那句"只依据资料"，它就只能说"资料里没有"。

`✏️` 推到底：**RAG 的价值取决于"资料的质量是否超过模型本来就有的知识"**——低于的话，它是负担。

**2. 分数高 ≠ 有答案。**

检索器**永远不会说"我不确定"**，它只会返回 k 个"最不讨厌的"。实测：真命中 **0.4424**、高相关但没答案 **0.4015**，只差 0.04——**单一阈值分不开**。

> **分数衡量的是「像不像」，不是「有没有答案」。** 这是两件不同的事。
