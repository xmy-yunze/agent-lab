# 产出物一 · 最小 Agent 循环

**状态：完工 ✅（2026-10-04）**

## 目标

亲手写出一个循环，让它自己决定下一步干什么。不是用框架，是自己写。

## 题目

写一个命令行程序。给它一句话任务，它自己去决定调用哪个工具、调几次，直到给出最终答案。

建议的场景（贴合后端）：

> 任务示例：「查一下用户 1001 的信息，然后判断他的密码能不能通过校验」

程序需要自己决定：先查用户 → 再拿密码去校验 → 最后给结论。

## 硬性要求

1. **必须是一个循环**（while），不是一条写死的 if-else 流水线。
2. **至少 2 个工具**。比如「查用户信息」「校验密码格式」，工具内部可以造假数据，不用真连库。
3. **每一轮必须打印**：模型打算干什么 → 实际调用了哪个工具、参数是什么 → 工具返回什么 → 下一步判断。
4. **必须有终止条件**。想清楚：怎么知道它该停了？如果模型一直要调工具怎么办？
5. **本阶段不许引 Agent 框架**（Spring AI、LangChain4j 都先别用）。可以手写 HTTP 调模型 API。

## 要搞明白的问题

做完之后，我应该能回答：

- 「下一步干什么」是**谁**在决定？是 if-else 还是模型？这个区别为什么是关键？
    1. 在 Agent 循环里，下一步由模型决定，我的 if-else 只识别它的决定，不做决策。模型决定四件事：**调不调、调哪个、参数填什么、什么时候停**。
    2. 关键是**形状从直线变环路**：RAG 五步写死是直线（模型只在最后当打字员），Agent loop 是环路（每圈模型点菜、我跑腿、回灌再问）。"下一步"的决定权从我手里搬到了模型手里。
    3. 证据：Day 2 日志 —— 第 1 轮模型自己点「查用户信息」，第 2 轮它把查到的密码传给「校验密码格式」，这两步顺序不是我安排的。
- 工具的「描述信息」（工具叫什么、要什么参数）为什么必须写清楚？它和**后端接口文档**是什么关系？
    1. 因为描述的**读者是模型，不是我的代码**（我的代码永远不读 description，只读 name 和 params）。描述不清，模型就瞎猜参数或拿别的工具顶 —— 跟接口文档写糊了同事只能猜是同一类事故。
    2. 和普通后端接口文档相比：接口文档面向开发者（人类）；工具描述面向大模型。两者**同构**：name=接口名、params=请求参数、required=必填标记 —— 一份契约两边读，模型照着点菜，代码照着实现。除了参数信息，工具描述还需补充业务规则与适用场景。
    3. 证据：Day 1 实测 —— 带 tools → 返回 tool_calls；不带 → 长篇搪塞。说明模型是照清单点菜的。
- **如果把工具从 2 个加到 10 个，我的代码需要改什么？** —— 这题的答案能说明 Agent 和传统后端的本质差别。
    1. 实测行数账 —— TOOL_LIST 加了 8 项定义，executeMockTool 的 switch 加了 8 个 case，ChatRunner 编排逻辑改了 0 行：循环、协议、三层刹车、日志都没变。
    2. 本质区别：Agent 把**业务决策交给模型**，调度框架通用；业务能力扩展只增加工具，不改动调度流程。传统程序所有分支、流程预先编码在代码中，能力扩张就要修改控制流。
    3. 根因：**工具的发现和分发是模型做的，不是代码路由的**，所以编排层不随工具数增长。
- 循环的终止条件为什么不能只靠「模型说结束了」？
    1. 会一直不停的说，导致 token 烧完 —— 对应**轮数上限（超时保护）**。
    2. 工具坏掉一直重试 —— 对应**连续失败上限（熔断）**。⚠️ "连续"是语义核心：成功要清零，否则退化成"总失败计数器"。
    3. 谎报结束 —— 它可能说"已完成"但其实没做（见 Day 4 坏菜单实验）。
    4. 三层合起来就是**死循环保护**：正常返回 / 超时 / 熔断。
    5. 证据：Day 3 日志 —— mockQueryUser 永远 throw，模型连挂 3 次还在原样重试，最后是熔断（consecutiveFail >= 3）才停的，不是它自己说停。

## 验收标准

- [x] 打印的日志能让我看清每一轮发生了什么，出问题能定位
- [x] 上面四个问题都能口头讲清楚

## 提示（卡住了再看）

<details>
<summary>关于「谁在决定下一步」</summary>

传统后端是写死的：if 用户不存在 then 报错。Agent 是把「有哪些工具可用」告诉模型，让模型来选。所以工具的数量变了，代码不用改，只要注册进去——这是最关键的一步跨越。

</details>

<details>
<summary>关于终止条件</summary>

至少要有三层保护：模型自己给出最终答案（正常结束）、循环轮数上限（防死循环）、工具连续失败次数上限（防卡死）。想想生产环境里，这三层分别对应你熟悉的哪个后端机制。

</details>
